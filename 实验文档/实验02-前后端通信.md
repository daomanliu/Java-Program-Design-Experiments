# 实验二　前后端通信（test2）

> 对应工程：`test2`　｜　前置实验：无（建议先做实验一）　｜　端口：8080

## 一、实验目标

1. 理解 **浏览器（前端）↔ Spring Boot（后端）** 之间用 JSON 传数据；
2. 会用 `@PostMapping` + `@RequestBody` 接收 JSON；
3. 会写统一的返回体 `Result<T>`（后面 8 个实验都会用它）；
4. 会用 Lombok 简化实体类；
5. 会用 Apifox 测试 POST 接口，并理解 **"业务码"和"HTTP 状态码"不是一回事**。

---

## 二、原理速览

### 2.1 一次登录请求经历了什么

```text
login.html 页面
   │  fetch('/login', {method:'POST',
   │                   headers:{'Content-Type':'application/json'},
   │                   body: JSON.stringify({name:'test', password:'test'})})
   ▼
Tomcat(8080) → DispatcherServlet → LoginController.login(@RequestBody User user)
   │
   │  Spring 用 Jackson 把 {"name":"test","password":"test"} 反序列化成一个 User 对象
   ▼
业务判断：和内存里的 test 用户比对
   │
   ▼
return Result.success("登录成功", user)
   │  Jackson 再把 Result 序列化成 JSON
   ▼
HTTP 200
{ "code": 200, "msg": "登录成功", "data": { "name": "test", "password": "test" } }
   │
   ▼
login.html 用 fetch 拿到 data，判断 data.code === 200，显示成功
```

### 2.2 三个关键注解

| 注解 | 作用 |
|------|------|
| `@PostMapping("/login")` | 绑定 POST 请求 |
| `@RequestBody` | 表示"把请求体 JSON 反序列化成这个参数" |
| `@Data`（Lombok） | 自动生成 `getter/setter/toString/equals/hashCode` |

> 没有 `@RequestBody` 时，Spring 会当成 **表单参数** 处理，JSON 就传不进来了。

### 步骤 3：写统一返回体 `Result`

**文件路径**：`test2/src/main/java/com/daomanliu/test2/common/Result.java`

在 `com.daomanliu.test2` 下新建包 `common`，再建类 `Result`：

```java
package com.daomanliu.test2.common;

import lombok.AllArgsConstructor;
import lombok.Data;

@Data
@AllArgsConstructor
public class Result<T> {
    private int code;
    private String msg;
    private T data;

    public static <T> Result<T> success(T data) {
        return new Result<T>(200, "success", data);
    }
    public static <T> Result<T> success(String msg, T data) {
        return new Result<T>(200, msg, data);
    }
    public static <T> Result<T> fail(int code, String msg) {
        return new Result<T>(code, msg, null);
    }
}
```

**逐行解释：**

| 代码 | 说明 |
|------|------|
| `class Result<T>` | 泛型类。`T` 是真正的业务数据类型，可以是 `User`、`String`、`List<User>` |
| `@Data` | Lombok 自动生成 getter/setter/toString，Jackson 序列化就靠 getter |
| `@AllArgsConstructor` | 自动生成三参构造方法，所以下面能 `new Result<T>(200, "success", data)` |
| `success(T data)` | 两个重载：不传提示语时用 `"success"` |
| `fail(int code, String msg)` | 失败时 `data` 固定为 `null` |

**为什么要有这个类？**
如果每个接口都直接返回 `User` 或者 `String`，前端就没法统一判断"成功还是失败"。有了 `Result`，前端只认一个字段 `code`，代码简洁很多。**从实验二一直用到实验十，后面不用再改它。**

### 步骤 4：写实体类 `User`

**文件路径**：`test2/src/main/java/com/daomanliu/test2/entity/User.java`

新建包 `entity`，再建类 `User`：

```java
package com.daomanliu.test2.entity;

import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;

@Data
@AllArgsConstructor
@NoArgsConstructor
public class User {
    private String name;
    private String password;
}
```

**三个 Lombok 注解各管什么：**

| 注解 | 生成的内容 | 为什么需要 |
|------|-----------|-----------|
| `@Data` | getter/setter/equals/hashCode/toString | Jackson 序列化需要 getter；下面比较用户需要 `equals` |
| `@AllArgsConstructor` | 全参构造 `User(String, String)` | 代码里 `new User("test", "test")` 要用 |
| `@NoArgsConstructor` | 无参构造 | **Jackson 反序列化需要**，没有它接收 JSON 会报错 |

> ⚠️ 新手最常见的坑：只写 `@Data` 不写 `@NoArgsConstructor`，Lombok 就不会生成无参构造，Jackson 反序列化直接 400。

### 步骤 5：写登录接口

**文件路径**：`test2/src/main/java/com/daomanliu/test2/controller/LoginController.java`

新建包 `controller`，再建类 `LoginController`：

```java
package com.daomanliu.test2.controller;

import com.daomanliu.test2.common.Result;
import com.daomanliu.test2.entity.User;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;


@RestController
public class LoginController {
    User test = new User("test", "test");
    @PostMapping("/login")
    public Result<User> login(@RequestBody User user) {
        if (test.equals(user)) {
            return Result.success("登录成功", user);
        } else {
            return Result.fail(401, "登录错误");
        }

    }
}
```

**逐行解释：**

| 代码 | 说明 |
|------|------|
| `User test = new User("test", "test");` | 模拟数据库里已经存在的用户。**还没连数据库**，这是本实验的重点：先把"通信"跑通 |
| `@PostMapping("/login")` | 只接受 POST |
| `@RequestBody User user` | 把 JSON `{"name":"test","password":"test"}` 变成一个 `User` 对象 |
| `test.equals(user)` | `@Data` 生成的 `equals` 会比较 `name` 和 `password` 两个字段 |
| `Result.success("登录成功", user)` | 调用带 msg 的重载 |
| `Result.fail(401, "登录错误")` | 登录失败：**HTTP 还是 200**，只有 body 里的 `code` 是 401 |

> 注意 `Result<User>` 这个返回类型：写泛型能让 IDEA 给出类型提示，实际序列化结果一样。

### 步骤 6：准备前端页面

**文件路径**：`test2/src/main/resources/static/login.html`

**这个文件不用你写**，直接从工程里复制过去即可。它做的事情是：

| 行为 | 对应代码 |
|------|----------|
| 点"登录"按钮 | `onclick="doLogin()"` |
| 把输入框的值变成 JSON | `JSON.stringify({name:..., password:...})` |
| POST 到后端 | `fetch('/login', {method:'POST', headers:{'Content-Type':'application/json'}, body:...})` |
| 根据 `data.code` 显示成功/失败 | `if (data.code === 200) ... else ...` |

> 页面里的注释也写明了：**Result 的字段是 code / msg / data**。

## 五、接口测试（Apifox）

对应 `接口测试文档.md` 中的 **「POST test2登录测试」**。

### 5.1 成功用例

| 项 | 填写 |
|----|------|
| 方法 | `POST` |
| URL | `{{baseUrl}}/login` |
| Header | `Content-Type: application/json`（Apifox 选 Body=json 会自动带） |
| Body（json） | `{"name": "test", "password": "test"}` |

**期望返回**：

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "name": "test",
    "password": "test"
  }
}
```

断言建议：

| 断言类型 | 表达式 | 期望值 |
|----------|--------|--------|
| JSON 字段 | `$.code` | `200` |
| JSON 字段 | `$.msg` | `登录成功` |
| JSON 字段 | `$.data.name` | `test` |

### 5.2 失败用例

Body 改成：

```json
{"name": "test", "password": "wrong"}
```

**期望返回**：

```json
{
  "code": 401,
  "msg": "登录错误",
  "data": null
}
```

> 🔍 **重点观察**：右侧状态码仍然是 **200 OK**！
> 因为 Controller 正常返回了 `Result`，Spring 就认为请求处理成功了。
> 如果想让 HTTP 状态码也变成 401，需要返回 `ResponseEntity` 或加 `@ResponseStatus`——本实验故意不这么做，就是为了让你分清两层状态码。

### 5.3 边界用例（体会一下 Spring 的容错）

| 请求体 | 现象 | 原因 |
|--------|------|------|
| `{}` | code=401，msg="登录错误" | name/password 都是 null，equals 不相等 |
| `{"name":"test"}` | code=401 | password 为 null |
| 不是合法 JSON（少了引号） | HTTP **400** | Jackson 反序列化失败 |
| 不选 json，选了 form-data | HTTP **415** | 没有匹配的 `Content-Type` |

### 5.4 保存为测试用例

Apifox 里点 **保存** → 在接口上右键 **另存为用例**，把"成功"和"失败"两条都存下来，以后回归测试一键跑。

## 七、常见问题（FAQ）

### Q1：发送请求报 415 Unsupported Media Type

没有带 `Content-Type: application/json`。在 Apifox 里把 Body 类型选成 **json**，它会自动加。

### Q2：报 400，控制台有 `HttpMessageNotReadableException`

JSON 格式错（比如少逗号、用了单引号），或者 `User` 缺少 `@NoArgsConstructor`。

### Q3：返回的 data 是 null

说明走了 `Result.fail` 分支。打印一下收到的 `user`，看 name/password 有没有传对。

### Q4：`test.equals(user)` 为什么要反过来写？

`test` 一定不为 null，所以不会空指针。如果写成 `user.equals(test)`，万一 `user` 是 null 就崩了。**"常量/已知对象放在 equals 左边"是好习惯。**

### Q5：为什么用户名密码是写死在内存里的？

因为本实验只讲"通信"。真正的数据库校验在实验六（JDBC）和实验七（JPA）。

### Q6：前端页面 404

确认文件在 `src/main/resources/static/` 下（不是 `templates`），文件名是 `login.html`（全小写）。

### Q7：改了 HTML 但页面没变

浏览器缓存。按 `Ctrl+F5` 强制刷新。

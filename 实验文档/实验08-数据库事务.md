## 一、实验目标

1. 理解 **事务（Transaction）** 与 **ACID**；
2. 会用 `@Transactional` 把"多条写操作"变成一个原子操作；
3. 理解什么情况下事务会**回滚**、什么情况下**不会**；
4. 会用 `@Modifying + @Query` 执行自定义的增删改；
5. 亲手做一次"**中途失败 → 数据全部回滚**"的验证实验；
6. 能从日志/数据库两处证明事务生效。

## 二、原理速览

### 2.1 为什么需要事务

实验七的注册只写一张表（`users`），没什么风险。但真实的注册要做三件事：

```text
① insert into users      (新增用户)
② insert into roles      (如果没有 USER 角色，就创建)
③ insert into user_role  (把用户和角色关联起来)
```

如果 ① 成功、② 成功、③ 失败（比如数据库连接断了），会留下什么？

- 用户能登录（因为 users 里有记录）；
- 但没有任何角色 → 所有受保护接口都 403；
- 而且这个人**再也没法注册**（用户名已存在）。

**这就是"脏数据"。事务要保证的，就是这三步"要么全成功，要么全失败"。**

### 2.2 ACID

| 字母 | 含义 | 在这个实验里的体现 |
|------|------|-------------------|
| **A** 原子性 Atomicity | 要么全做，要么全不做 | 三步任一失败，全部撤销 |
| **C** 一致性 Consistency | 数据始终满足约束 | `user_role` 不会出现"用户不存在"的孤儿记录 |
| **I** 隔离性 Isolation | 并发事务互不干扰 | 两个用户同时注册不会互相看到对方没提交的数据 |
| **D** 持久性 Durability | 提交后永久保存 | 断电重来数据还在 |

### 2.3 Spring 的声明式事务

只要在方法上加 `@Transactional`，Spring 就会用 **AOP 代理**把它包起来：

```text
调用 register()
   │
   ▼
代理对象：开启事务（conn.setAutoCommit(false)）
   │
   ├─ 执行方法体（所有 SQL 用同一个连接）
   │     ├─ 成功 → 提交（commit）
   │     └─ 抛异常 → 回滚（rollback）
   ▼
代理对象：关闭/归还连接
```

**关键点：**

- 方法体里**所有数据库操作必须用同一个连接**，否则事务管不到——Spring 通过"把连接绑定到当前线程"来解决；
- **默认只对 `RuntimeException` 和 `Error` 回滚**，受检异常（`Exception`）**不回滚**！（重要，见 FAQ）

### 步骤 6：新建 RoleRepository（本实验新增）

**文件路径**：`test8/src/main/java/com/daomanliu/test8/repository/RoleRepository.java`

```java
package com.daomanliu.test8.repository;

import com.daomanliu.test8.entity.Role;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Modifying;
import org.springframework.data.jpa.repository.Query;

import java.util.List;

public interface RoleRepository extends JpaRepository<Role, Long> {

    Role findByName(String name);

    @Modifying
    @Query(value = "insert into user_role (user_id, role_id) values (?1, ?2)", nativeQuery = true)
    int insertUserRole(Long userId, Long roleId);


    @Query(value = "select r.* from roles r join user_role ur on r.id = ur.role_id where ur.user_id = ?1", nativeQuery = true)
    List<Role> findRolesByUserId(Long userId);
}
```

**三个方法逐个说：**

#### ① `Role findByName(String name)`

派生查询，返回单个对象（不是 `Optional`）。查不到返回 `null`——所以 AuthController 里要判空。

#### ② `@Modifying` 的插入

```java
@Modifying
@Query(value = "insert into user_role (user_id, role_id) values (?1, ?2)", nativeQuery = true)
int insertUserRole(Long userId, Long roleId);
```

| 注解 | 为什么必须加 |
|------|-------------|
| `@Query` | 自定义 SQL：往中间表插一条关联 |
| `nativeQuery = true` | 用原生 SQL（因为 `user_role` 没有实体） |
| `@Modifying` | **告诉 Spring "这是写操作"**。不加会抛 `InvalidDataAccessApiUsageException: Expecting a SELECT query` |

**返回值 `int` 是受影响的行数。**

> ⚠️ `@Modifying` 的查询**必须在事务中执行**，否则抛 `TransactionRequiredException: Executing an update/delete query`。这正是下一步加 `@Transactional` 的原因之一。

#### ③ 查角色

和 test7 里的一样，只是换了个"家"。

### 步骤 7：给注册接口加事务（本节核心）

**文件路径**：`test8/src/main/java/com/daomanliu/test8/controller/AuthController.java`

```java
package com.daomanliu.test8.controller;

import com.daomanliu.test8.common.JwtUtils;
import com.daomanliu.test8.common.Result;
import com.daomanliu.test8.entity.Role;
import com.daomanliu.test8.entity.User;
import com.daomanliu.test8.repository.RoleRepository;
import com.daomanliu.test8.repository.UserRepository;
import jakarta.transaction.Transactional;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

import java.util.List;

@RestController
public class AuthController {

    private final BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
    private final UserRepository userRepository;
    private final RoleRepository roleRepository;

    public AuthController(UserRepository userRepository, RoleRepository roleRepository) {
        this.userRepository = userRepository;
        this.roleRepository = roleRepository;
    }

    @PostMapping("/register")
    @Transactional
    public Result<String> register(@RequestBody User user) {
        if (user.getName() == null || user.getPassword() == null) {
            return Result.fail(400, "用户名和密码不能为空");
        }
        if (userRepository.findByName(user.getName()).isPresent()) {
            return Result.fail(400, "用户名已存在");
        }
        user.setPassword(encoder.encode(user.getPassword()));
        userRepository.save(user);
        Role userRole = roleRepository.findByName("USER");
        if (userRole == null) {
            userRole = roleRepository.save(new Role(null, "USER"));
        }
        roleRepository.insertUserRole(user.getId(), userRole.getId());
        return Result.success("注册成功", null);
    }

    @PostMapping("/login")
    public Result<String> login(@RequestBody User user) {
        User dbUser = userRepository.findByName(user.getName()).orElse(null);
        if (dbUser == null || !encoder.matches(user.getPassword(), dbUser.getPassword())) {
            return Result.fail(401, "用户名或密码错误");
        }
        List<String> roles = roleRepository.findRolesByUserId(dbUser.getId())
                .stream().map(r -> "ROLE_" + r.getName()).toList();
        String token = JwtUtils.generate(dbUser.getName(), roles);
        return Result.success("登录成功", token);
    }
}
```

**和 test7 的差异一览：**

| 变化 | 说明 |
|------|------|
| 类上加 `final RoleRepository roleRepository` + 构造参数 | 注入第二个 Repository |
| `register` 上方加 `@Transactional` | **把整个方法包进一个事务** |
| 注册体里多了两步：查/建 USER 角色、插关联表 | 一次请求写三张表 |
| 登录时角色查询改用 `roleRepository` | 职责划分 |

#### 注册的三步写入，必须在同一个事务里

```java
userRepository.save(user);                               // ① users
Role userRole = roleRepository.findByName("USER");       // ② roles（查）
if (userRole == null) userRole = roleRepository.save(new Role(null, "USER"));  // ② roles（建）
roleRepository.insertUserRole(user.getId(), userRole.getId());                 // ③ user_role
```

- ① 之后，`user.getId()` **立刻就有值了**（自增主键回填），这是后面能插关联表的前提；
- ② 是"如果没有 USER 角色就创建一个"，保证新用户一定能登录；
- ③ 是 `@Modifying` 的原生插入。

#### 关于导入的 `jakarta.transaction.Transactional`

工程用的是 **Jakarta 标准注解**，不是 Spring 的 `org.springframework.transaction.annotation.Transactional`。

| | `jakarta.transaction.Transactional`（本工程） | Spring 的 `@Transactional` |
|---|---|---|
| 谁支持 | Spring 也能识别并交给事务管理器 | Spring 原生 |
| 指定异常 | `rollbackOn = ...` | `rollbackFor = ...` |
| 隔离级别/超时/只读 | 不支持 | 支持 `isolation`、`timeout`、`readOnly` |
| 传播行为 | 不支持 | 支持 `propagation` |

> **两个都能用**，效果一致（都默认对 RuntimeException 回滚）。想用更细的控制，就换成 Spring 的那个。**注意别两个都 import，会冲突。**

### 步骤 12：验证"中途失败 → 全部回滚"（可选，但强烈建议做）

> ⚠️ 下面的改动**只用于验证**，验证完请**立刻删掉**。我没有改你的代码，这一步由你手动完成。

在 `register` 方法的最后一行（`return` 之前）临时插入一句：

```java
roleRepository.insertUserRole(user.getId(), userRole.getId());
throw new RuntimeException("故意抛异常，验证事务回滚");   // ← 临时加这一行
return Result.success("注册成功", null);
```

然后：

1. 重启，注册一个新用户 `tx_fail` / `123456`；
2. 浏览器/前端会看到 **500** 错误；
3. 去数据库查：

```sql
SELECT * FROM users WHERE name = 'tx_fail';      -- 应该查不到（已回滚）
SELECT COUNT(*) FROM user_role;                  -- 数量没有增加
```

4. **把那一行删掉**，重启，再注册一次 `tx_fail` → 这次能成功。

**这说明什么？**

- 前面三条 INSERT 都已经执行了，但因为方法最后抛了 `RuntimeException`，Spring **回滚了整个事务**；
- 如果 **没有** 加 `@Transactional`，`users` 里就会**留下一条脏记录**（这就是我们要避免的）。

> 💡 更深一步：想看到"没有事务会怎样"，把 `@Transactional` 注释掉，同样插入 throw，再注册一次，然后查数据库——你会发现 users 表里**多了一条记录**。这个对比实验最能说明问题。

## 八、常见问题（FAQ）

### Q1：`@Transactional` 加了却不起作用

四个最常见的失效场景：

| 场景 | 说明 | 解决 |
|------|------|------|
| **同类内部调用** | `this.otherMethod()` 不经过代理，注解失效 | 拆到别的 Bean，或注入自己 |
| **方法不是 public** | Spring 默认只代理 public 方法 | 改 public |
| **异常被自己 catch 了** | 没抛出 → 代理感知不到 | 别 catch，或 catch 后重新抛 |
| **抛的是受检异常** | 默认只回滚 `RuntimeException`/`Error` | 用 Spring 注解并加 `rollbackFor = Exception.class` |

### Q2：报 `TransactionRequiredException: Executing an update/delete query`

`@Modifying` 查询没在事务里。给调用方方法加 `@Transactional`。

### Q3：报 `Expecting a SELECT query`

`@Modifying` 没加。

### Q4：注册报 500，日志里是 `Table 'test6.user_role' doesn't exist`

库表没建全，回到实验六执行建表 SQL。

### Q5：第一次注册后 roles 表里有两个 USER？

- 并发注册时可能出现（两个线程同时判断"角色不存在"）；
- 表上已有 `UNIQUE` 约束，第二个会插入失败并回滚 —— **这正是事务在保护你**。

### Q6：登录后 roles 是空的，但数据库里明明有关联

token 里的角色是**登录时**读的。如果你是在授权之前登录的，重新登录即可。

### Q7：回滚验证时，数据库里还是有记录

- 确认抛的是 `RuntimeException`（比如 `RuntimeException`、`IllegalStateException`），不是受检异常；
- 确认 `@Transactional` 加在 **public** 的 `register` 上，且是 Controller 被 Spring 直接调用的（本工程满足）；
- 确认修改后**重启**了。

### Q8：能不能在 Controller 上加 @Transactional？

能，本工程就是。但更规范的做法是放到 **Service 层**——Controller 只负责"收请求、转交、返回"。本实验为了少建一层，直接写在 Controller 上，**生产项目建议移到 Service**。

### Q9：事务里能不能发 HTTP 请求？

能，但**很危险**：事务会一直持有数据库连接，第三方接口一慢，连接池就被占满。规范做法是"事务内只做数据库操作"。

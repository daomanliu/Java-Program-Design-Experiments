# 实验十　AI 大模型调用（test10）

> 对应工程：`test10`　｜　来源：由 **test4** 演进而来　｜　端口：8080
>
> 本实验做两件事：
> ① 让后端通过 **Spring AI** 调用大模型（DeepSeek）；
> ② 让大模型**调用我们自己写的天气接口**（Tool / Function Calling），再用流式（SSE）把回答边生成边吐给前端。

## 一、实验目标

1. 理解"调用大模型"本质上就是**一次 HTTP POST**（OpenAI 兼容协议）；
2. 会用 Spring AI 的 `ChatClient` 发一次对话；
3. 理解 **Tool Calling（工具调用）**：让模型"决定"去调用你写的 Java 方法；
4. 会用 `@Tool` 注解把天气查询能力"注册"给模型；
5. 理解 **SSE 流式输出**，会用 `Flux<String>` 边算边返回；
6. 会用 Apifox / curl 测试流式接口。

---

## 二、原理速览

### 2.1 大模型接口长什么样

主流大模型（OpenAI、DeepSeek、通义、Kimi……）都提供了 **OpenAI 兼容**的接口：

```text
POST https://api.deepseek.com/v1/chat/completions
Authorization: Bearer sk-xxxx
Content-Type: application/json

{
  "model": "deepseek-chat",
  "messages": [
    { "role": "system", "content": "你是一个友好的中文助手" },
    { "role": "user",   "content": "北碚今天天气怎么样" }
  ],
  "stream": false
}
```

返回：

```json
{
  "choices": [
    { "message": { "role": "assistant", "content": "今天北碚多云，21 度..." } }
  ]
}
```

**Spring AI 就是把这套东西封装成 `ChatClient`，让你不用手写 HTTP。**

### 2.2 Tool Calling（本实验的精华）

普通对话，模型只能"凭记忆"回答，问天气它只能编。Tool Calling 让它**有工具可用**：

```text
用户：北碚今天天气怎么样？
   │
   ▼
模型（第 1 轮）：我需要调用工具 getWeather(city="北碚")
   │
   ▼  Spring AI 自动执行
WeatherToolService.getWeather("北碚")
   │  → WeatherService → 和风天气 API → 返回一段中文描述
   ▼
把工具结果再发回模型（第 2 轮）
   │
   ▼
模型：今天北碚多云，气温 21°C，体感 20°C……
```

**关键在于：模型并不真的会"打电话"，它只是输出一个"我要调用 getWeather"的结构化指令，由 Spring AI 在本地执行，再把结果喂回去。**

### 2.3 SSE 流式输出

普通响应：等模型全部生成完，一次性返回（用户要干等好几秒）。
流式响应：模型每生成几个字就推一次，前端"打字机"效果。

| | 普通 | 流式 |
|---|---|---|
| 后端返回 | `Result<String>` | `Flux<String>` |
| Content-Type | `application/json` | `text/event-stream` |
| 前端读取 | `resp.json()` | `resp.body.getReader()` 逐块读 |
| 感知 | 等 5 秒突然出现 | 立刻开始"打字" |

### 步骤 4：把天气查询抽成 Service

**文件路径**：`test10/src/main/java/com/daomanliu/test10/service/WeatherService.java`

新建包 `service`，建类 `WeatherService`：

```java
package com.daomanliu.test10.service;

import com.daomanliu.test10.dto.GeoResponse;
import com.daomanliu.test10.dto.WeatherResponse;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.http.client.HttpComponentsClientHttpRequestFactory;
import org.springframework.stereotype.Service;
import org.springframework.web.client.RestTemplate;
import org.springframework.web.util.UriComponentsBuilder;

import java.net.URI;
import java.nio.charset.StandardCharsets;

@Service
public class WeatherService {

    @Value("${qweather.host}")
    private String host;

    @Value("${qweather.key}")
    private String key;

    private final RestTemplate restTemplate = new RestTemplate(new HttpComponentsClientHttpRequestFactory());

    public WeatherInfo getWeather(String city) {
        URI geoUri = UriComponentsBuilder
                .fromUriString(host + "/geo/v2/city/lookup")
                .queryParam("location", city)
                .queryParam("key", key)
                .build()
                .encode(StandardCharsets.UTF_8)
                .toUri();

        GeoResponse geo = restTemplate.getForObject(geoUri, GeoResponse.class);
        if (geo == null || geo.getLocation() == null || geo.getLocation().isEmpty()) {
            return null;
        }

        GeoResponse.Location loc = geo.getLocation().get(0);
        String url = host + "/weather/v1/current/" + loc.getLat() + "/" + loc.getLon() + "?key=" + key;
        WeatherResponse w = restTemplate.getForObject(url, WeatherResponse.class);
        if (w == null || w.getCondition() == null) {
            return null;
        }
        return new WeatherInfo(loc, w);
    }

    public record WeatherInfo(GeoResponse.Location location, WeatherResponse weather) {}

}
```

**和 test4 的差异：**

| 变化 | 说明 |
|------|------|
| 类上加了 `@Service` | 变成 Spring Bean，可以被注入到 Controller 和 Tool 里 |
| 方法从 Controller 挪到 Service | Controller 只负责"收请求、返结果"，业务逻辑归 Service（**分层**） |
| 返回 `WeatherInfo` 记录类 | 把"城市信息 + 天气"打包返回，方便调用方使用 |
| 没有做两位小数的经纬度截断 | 直接用原始值（和风也能接受） |

**`record` 是什么？**
Java 14+ 的记录类，一行就等价于"final 字段 + 全参构造 + 取值方法 + equals/hashCode"。这里 `new WeatherInfo(loc, w)` 之后用 `info.location()`、`info.weather()` 取值（**注意是 `location()` 不是 `getLocation()`**）。

### 步骤 5：写工具类（让模型能"叫得动"）

**文件路径**：`test10/src/main/java/com/daomanliu/test10/service/WeatherToolService.java`

在 `service` 包里建类 `WeatherToolService`：

```java
package com.daomanliu.test10.service;

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.stereotype.Service;

@Service
public class WeatherToolService {
    private final WeatherService weatherService;

    public WeatherToolService(WeatherService weatherService) {
        this.weatherService = weatherService;
    }

    @Tool(description = "查询指定中国城市的实时天气，包括天气状况、温度、体感温度、湿度、风向风速、气压、能见度。当用户询问任何城市的天气时必须调用。")
    public String getWeather(String city) {
        WeatherService.WeatherInfo info = weatherService.getWeather(city);
        if (info == null) {
            return "未找到城市或查询失败: " + city;
        }
        var w = info.weather();
        var loc = info.location();
        return String.format(
                "%s（%s）当前天气：%s，温度 %.1f%s，体感 %.1f%s，湿度 %d%%，风向 %s，风速 %.1f %s（%d级），气压 %.0f %s，能见度 %.1f km",
                loc.getName(), loc.getAdm1(),
                w.getCondition().getText(),
                w.getTemperature().getValue(), w.getTemperature().getUnit(),
                w.getFeelsLike().getValue(), w.getFeelsLike().getUnit(),
                (int) Math.round(w.getHumidity() * 100),
                w.getWind().getDirection().getCompass().toUpperCase(),
                w.getWind().getSpeed().getValue(), w.getWind().getSpeed().getUnit(),
                w.getWind().getScale(),
                w.getPressure().getValue(), w.getPressure().getUnit(),
                w.getVisibility().getValue() / 1000
        );
    }
}
```

**三个要点：**

#### ① `@Tool` 注解

```java
@Tool(description = "查询指定中国城市的实时天气……当用户询问任何城市的天气时必须调用。")
```

- 这个注解让方法**暴露给大模型**；
- `description` 就是给模型看的"使用说明书"——**写得越清楚，模型越知道什么时候该调**；
- 参数 `city` 的类型和名字也会一起发给模型，让它知道要传一个字符串。

> 想给参数加说明，可以用 `@ToolParam(description = "城市名，例如：北京、北碚")`。本工程没加，靠方法签名也能工作。

#### ② 返回值用"自然语言"

方法返回的是**一段中文**：

```text
北碚（重庆市）当前天气：多云，温度 21.0°C，体感 20.1°C，湿度 68%，风向 S，风速 3.2 km/h（2级），气压 1002 hPa，能见度 12.0 km
```

**为什么不返回 JSON？** 因为这段文本会**原样喂回给模型**，模型再据此组织回答。自然语言对模型最友好。

#### ③ 数据换算

| 字段 | 处理 | 原因 |
|------|------|------|
| `humidity` | 乘 100 再四舍五入 | 和风返回 0~1 的小数 |
| `visibility` | 除以 1000 | 单位是米，除以 1000 变成公里 |
| `compass` | `toUpperCase()` | 返回小写 `s`，转成 `S` 更好看 |

### 步骤 6：改造天气接口（复用 Service）

**文件路径**：`test10/src/main/java/com/daomanliu/test10/controller/WeatherController.java`

```java
package com.daomanliu.test10.controller;

import com.daomanliu.test10.common.Result;
import com.daomanliu.test10.service.WeatherService;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/weather")
public class WeatherController {

    private final WeatherService weatherService;

    public WeatherController(WeatherService weatherService) {
        this.weatherService = weatherService;
    }

    @GetMapping
    public Result<WeatherService.WeatherInfo> getWeather(@RequestParam("city") String city) {
        WeatherService.WeatherInfo info = weatherService.getWeather(city);
        if (info == null) {
            return Result.fail(404, "找不到城市: " + city);
        }
        return Result.success(info);
    }
}
```

**和 test4 对比：**

| test4 | test10 |
|-------|--------|
| 所有逻辑写在 Controller | 逻辑在 Service，Controller 只有 5 行 |
| 返回 `Result<WeatherResponse>` | 返回 `Result<WeatherInfo>`（带城市信息） |
| 直接调 RestTemplate | 注入 Service |

> 这个接口**和 AI 无关**，但它验证了"底层能力是好的"。**先让 /weather 通，再去调 /chat**，是两个独立的故障域。

### 步骤 7：写聊天接口（本实验核心）

**文件路径**：`test10/src/main/java/com/daomanliu/test10/controller/ChatController.java`

在 `controller` 包建类 `ChatController`：

```java
package com.daomanliu.test10.controller;

import com.daomanliu.test10.service.WeatherToolService;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.messages.*;
import org.springframework.http.MediaType;
import org.springframework.web.bind.annotation.*;
import reactor.core.publisher.Flux;

import java.util.ArrayList;
import java.util.List;

@RestController
@RequestMapping("/chat")
public class ChatController {

    private final ChatClient chatClient;

    public ChatController(ChatClient.Builder builder, WeatherToolService weatherToolService) {
        this.chatClient = builder
                .defaultSystem("你是一个友好的中文助手。用户问天气时，请调用天气工具获取实时数据后再回答，不要编造天气信息。")
                .defaultTools(weatherToolService)
                .build();
    }

    public record ChatMessage(String role, String content) {}

    @PostMapping(produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<String> chat(@RequestBody List<ChatMessage> messages) {
        List<Message> promptMessages = new ArrayList<>();
        for (ChatMessage m : messages) {
            if ("user".equals(m.role())) {
                promptMessages.add(new UserMessage(m.content()));
            } else {
                promptMessages.add(new AssistantMessage(m.content()));
            }
        }

        return chatClient.prompt()
                .messages(promptMessages)
                .stream()
                .content()
                .onErrorResume(e -> Flux.just("[[ERROR]]" + e.getMessage()));
    }
}
```

**逐段讲透（这是全课最重要的 20 行）：**

#### ① 注入 `ChatClient.Builder`

```java
public ChatController(ChatClient.Builder builder, WeatherToolService weatherToolService) {
```

- Spring AI 的 starter 会自动配置一个 `ChatClient.Builder` Bean（已经读好了 yaml 里的 base-url / key / model）；
- 我们拿它来"定制"自己的客户端，**不要**自己 new。

#### ② 三个构建动作

```java
builder
    .defaultSystem("你是一个友好的中文助手……不要编造天气信息。")  // 系统提示词
    .defaultTools(weatherToolService)                            // 挂载工具
    .build();
```

| 动作 | 作用 |
|------|------|
| `defaultSystem(...)` | **系统提示词**，每次对话都带上，相当于"人设 + 规则"。这里明确要求"问天气必须调工具"，能显著提高工具被调用的概率 |
| `defaultTools(...)` | 把带 `@Tool` 方法的 Bean 注册进去。**不写这一句，模型永远不会调用你的天气方法** |
| `build()` | 生成 `ChatClient`，线程安全，可以复用 |

> 注意：构造方法里只做一次，**不要每次请求都 build**。

#### ③ 请求体结构

```java
public record ChatMessage(String role, String content) {}
```

前端传的是**整个对话历史**（一个数组）：

```json
[
  { "role": "user", "content": "北碚今天天气怎么样" }
]
```

多轮对话就是：

```json
[
  { "role": "user", "content": "北碚今天天气怎么样" },
  { "role": "assistant", "content": "今天北碚多云……" },
  { "role": "user", "content": "那明天呢" }
]
```

> **为什么要传历史？** 因为大模型 API **是无状态的**——它不记得上一次说了什么，上下文必须每次带全。

#### ④ 消息类型转换

```java
if ("user".equals(m.role())) {
    promptMessages.add(new UserMessage(m.content()));
} else {
    promptMessages.add(new AssistantMessage(m.content()));
}
```

前端用字符串 `"user"` / `"assistant"` 表示角色，Spring AI 用具体的 `Message` 对象，所以要转一下。

> 这里把"非 user 一律当 assistant"，是个简化写法（不严谨但够用）。

#### ⑤ 流式调用

```java
return chatClient.prompt()
        .messages(promptMessages)
        .stream()      // 关键：流式
        .content();    // 只要文本内容（不要元数据）
```

- `stream()` 返回的是 `Flux<ChatResponse>`；
- `.content()` 把它映射成 `Flux<String>`（每个元素是一小段文本）；
- 配合方法上的 `produces = TEXT_EVENT_STREAM_VALUE`，Spring 就会用 **SSE** 边收边推。

> 如果换成 `.call().content()`，就是**一次性**返回 `String`，前端要等全部生成完才有反应。

#### ⑥ 错误兜底

```java
.onErrorResume(e -> Flux.just("[[ERROR]]" + e.getMessage()))
```

- 流式接口一旦开始推数据，**HTTP 200 已经发出去了**，中途出错没法再改状态码；
- 所以只能"在流里塞一段错误文本"，前端识别 `[[ERROR]]` 前缀后显示错误；
- 不写这一句，出错时前端只会看到流突然断掉，很难排查。

### 步骤 8：前端页面

**文件路径**（直接复制，不用写）：

| 文件路径 | 作用 |
|----------|------|
| `test10/src/main/resources/static/chat.html` | AI 聊天页（流式 + Markdown + 公式渲染） |
| `test10/src/main/resources/static/weather.html` | 天气查询页（沿用 test4） |
| `test10/src/main/resources/static/lib/marked.min.js` | Markdown 解析库（chat.html 依赖） |
| `test10/src/main/resources/static/lib/katex/…` | 数学公式渲染库（chat.html 依赖） |

**访问地址**：
- 聊天：`http://localhost:8080/chat.html`
- 天气：`http://localhost:8080/weather.html`

**`chat.html` 的关键交互**（不用你写，但必须知道）：

| 能力 | 实现方式 |
|------|----------|
| 发送消息 | `fetch('/chat', {method:'POST', body: JSON.stringify(history)})` |
| **流式读取** | `resp.body.getReader()` + `TextDecoder`，按空行切分 SSE 事件 |
| 解析 SSE | 取每行以 `data:` 开头的内容，去掉前缀拼起来 |
| 边收边渲染 | `requestAnimationFrame` 节流，避免每个 token 都重绘 |
| Markdown 渲染 | `marked.parse()` |
| 公式渲染 | 先抠出 `$...$` / `$$...$$`，再交给 `katex.renderToString` |
| 错误显示 | 回复以 `[[ERROR]]` 开头时，显示到红色提示区 |

> ⚠️ **依赖注意**：`chat.html` 引用了 `/lib/marked.min.js` 和 `/lib/katex/…`。如果只复制了 html 没复制 `lib` 目录，页面会打不开或白屏。**整个 `static` 目录一起复制最保险。**

**最后用浏览器：**

1. 打开 `http://localhost:8080/chat.html`；
2. 输入"北碚今天天气怎么样" → 能边打字边显示，并且回答里**有真实温度/湿度**（说明工具真的被调用了）；
3. 再试试"用表格对比重庆和北京的天气，并解释质能方程 E=mc^2" → 能渲染表格和公式（这是 `chat.html` 的加分功能）。

## 六、接口测试（Apifox）

对应 `接口测试文档.md` 中的 **「POST test10AI聊天与天气查询测试」**。

### 6.1 天气接口（普通 JSON）

| 项 | 填写 |
|----|------|
| 方法 | `GET` |
| URL | `{{baseUrl}}/weather` |
| Query | `city` = `北碚` |

期望：`code=200`，`data.location.name` = `北碚`，`data.weather.temperature.value` 存在。

断言：

| 类型 | 表达式 | 期望 |
|------|--------|------|
| JSON 字段 | `$.code` | `200` |
| JSON 字段 | `$.data.weather.condition.text` | 非空 |

### 6.2 聊天接口（SSE 流式）

| 项 | 填写 |
|----|------|
| 方法 | `POST` |
| URL | `{{baseUrl}}/chat` |
| Header | `Content-Type: application/json`、`Accept: text/event-stream` |
| Body（json） | 见下 |

```json
[
  { "role": "user", "content": "北碚今天天气怎么样" }
]
```

**Apifox 里怎么看流式结果：**

1. 发送后，右侧响应区会自动显示 **"正在接收…"** 并逐条追加（新版 Apifox 支持 SSE）；
2. 如果看不到流式效果，切到 **原始（Raw）** 视图，能看到一坨 `data:xxx`；
3. 更保险的做法是用 **curl**（见步骤 9）。

> ⚠️ 断言注意：流式响应的 Body 不是 JSON，**不能用 `$.xxx` 断言**。可以断言：
> - HTTP 状态码 = `200`
> - 响应头 `Content-Type` 包含 `text/event-stream`
> - （弱断言）响应体包含关键词，比如 "北碚"

### 6.3 异常用例

| 用例 | 操作 | 期望 |
|------|------|------|
| 空消息 | Body 传 `[]` | 返回空流或错误文本（取决于模型） |
| key 错误 | 把 yaml 的 api-key 改错重启 | 流里出现 `[[ERROR]]` 开头的错误信息（含 401） |
| 城市不存在 | 问"阿斯加德天气" | 模型调用工具 → 工具返回"未找到城市" → 模型如实回答 |
| 不相关的问题 | 问"你好" | 不调用工具，直接回答 |

### 6.4 一个能体现"工具真的被调用"的测试

问：**"重庆和北京现在哪个更热？"**

- 如果工具没挂上，模型会**编**一个答案；
- 如果工具挂上了，它会**调用两次** `getWeather`（重庆、北京），然后比较。

对比两次的答案是否与 `/weather?city=重庆`、`/weather?city=北京` 的真实温度一致——**这是验证 Tool Calling 最直接的办法**。

## 八、常见问题（FAQ）

### Q1：启动报 401 / `Unauthorized`

- api-key 写错、过期、或账户没余额；
- 复制时带了空格或换行；
- 先按"3.2 用 curl 验证 key"排除账号问题。

### Q2：Maven 拉不到 `spring-ai-starter-model-openai:2.1.0-RC2`

RC 版本可能只在 milestone 仓库。按步骤 2 的提示加 `<repositories>`；或者把版本换成中央仓库里已有的 GA 版本（例如 1.0.x），并同步调整 API（GA 版本的包名可能有差异）。

### Q3：启动报 `No qualifying bean of type ChatClient.Builder`

- 依赖没加对（应该是 `spring-ai-starter-model-openai`）；
- yaml 里 `spring.ai.openai.api-key` 为空时，某些版本不会创建 Bean —— 先把 key 配上。

### Q4：聊天接口 404 / 415

- 404：路径是 `/chat`（类上 `@RequestMapping("/chat")` + 方法上无路径）；
- 415：没带 `Content-Type: application/json`。

### Q5：前端一直转圈，什么都没有

- 后端报错但被 `onErrorResume` 吞了：看返回里有没有 `[[ERROR]]`；
- 浏览器缓冲：确认后端 `produces` 是 `text/event-stream`；
- 检查 `chat.html` 所在的 `/lib` 目录有没有一起复制（缺 js 会白屏）。

### Q6：回答里天气是瞎编的

说明**工具没被调用**。依次检查：

1. `builder.defaultTools(weatherToolService)` 有没有写？
2. `WeatherToolService` 是不是 `@Service`、有没有被注入？
3. 方法上有没有 `@Tool(description = ...)`？
4. 系统提示词里有没有明确"问天气必须调用工具"？

> 还可以打开 Spring AI 的调试日志，在 yaml 里加：
> ``yaml
> logging:
>   level:
>     org.springframework.ai: DEBUG
> ```
> 这样能看到"工具调用的请求/结果"的完整往返。

### Q7：报 `model not found` / `invalid model`

模型名和账号不匹配。DeepSeek 常见的是 `deepseek-chat`、`deepseek-reasoner`；本工程用的是 `deepseek-flash`。以[官方文档](https://api-docs.deepseek.com)为准。

### Q8：报 `Connection timed out` / 很慢

- 网络问题（需要能访问 api.deepseek.com）；
- 模型本身生成慢（流式能缓解"体感"）；
- 工具里又调了一次和风接口，链路变长。

### Q9：回答到一半突然断了

- 模型侧超时/限流；
- 后端的 `Flux` 被取消（前端关闭了连接）；
- 查看后端日志里的异常。

### Q10：会花钱吗

会，按 token 计费。做实验时：
- 尽量用短问题；
- 不要写 while 循环狂刷；
- 用完把 key 停用/删除。

### Q11：能不能把 api-key 放前端

**绝对不行**。前端代码用户可见，key 会立刻被刷爆。**key 只能在后端**。

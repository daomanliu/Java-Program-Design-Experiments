# 实验三　文件传输（test3）

> 对应工程：`test3`　｜　前置实验：无　｜　端口：8080

## 一、实验目标

1. 理解 `multipart/form-data` 这种"传文件"的请求格式；
2. 用 `MultipartFile` 接收上传的文件，并保存到磁盘；
3. 用 `Files.list` 读取目录，返回文件列表；
4. 用 `ResponseEntity<Resource>` 实现文件下载；
5. 会用 `@Value` 读取配置文件里的路径；
6. 用 Apifox 测上传（form-data）和下载（保存二进制）。

---

## 二、原理速览

### 2.1 上传和普通 JSON 的区别

| | 普通 JSON 请求 | 文件上传请求 |
|---|---|---|
| Content-Type | `application/json` | `multipart/form-data; boundary=----xxx` |
| 请求体 | 一段文本 | 多个"部分"，每部分有自己的名字和类型 |
| 后端接收 | `@RequestBody` | `@RequestParam("file") MultipartFile` |

浏览器里是用 `FormData` 组装的：

```javascript
const formData = new FormData();
formData.append('file', input.files[0]);   // 字段名必须是 file，和后端 @RequestParam("file") 对上
fetch('/file/upload', { method: 'POST', body: formData });
```

> 注意：**不要**手动设置 `Content-Type`，浏览器会自动加上带 `boundary` 的值，设错了反而报 415。

### 2.2 下载是怎么实现的

后端把文件包装成 `Resource`，交给 Spring 输出字节流；关键在响应头：

```text
Content-Disposition: attachment; filename="xxx.txt"
```

`attachment` 表示"作为附件下载"，浏览器就会弹出保存框（而不是直接显示）。

## 三、实验步骤

### 步骤 1：新建工程 test3

坐标：Artifact `test3`，Package `com.daomanliu.test3`，依赖 **Spring Web** + **Lombok**。

### 步骤 2：准备上传目录

**先创建目录 `D:\upload`**（在资源管理器里新建文件夹即可）。

> ⚠️ 代码里 **没有** 自动创建目录的逻辑，目录不存在的话上传会抛 `NoSuchFileException`，接口返回 500。这是本实验最容易踩的坑。

如果你想放到别的地方，改下面的配置即可，注意 YAML 里的反斜杠 **要写两个**。

### 步骤 3：配置文件

**文件路径**：`test3/src/main/resources/application.yaml`

```yaml
spring:
  application:
    name: test3
  servlet:
    multipart:
      max-file-size: 10MB        # 单个文件最大 10MB
      max-request-size: 10MB     # 整个请求最大 10MB
file:
  upload-dir: D:\upload          # 上传目录（Windows 路径要写双反斜杠）
```

**逐项解释：**

| 配置 | 作用 |
|------|------|
| `spring.servlet.multipart.max-file-size` | 超过就报 `MaxUploadSizeExceededException`（HTTP 413 或被全局异常处理成 500） |
| `max-request-size` | 一次请求里所有文件加起来的上限 |
| `file.upload-dir` | **自定义配置**，不是 Spring 内置的，由 `@Value("${file.upload-dir}")` 读取 |

> 也可以写成 `D:/upload`（正斜杠），Java 在任何系统上都认，**比写双反斜杠更省心**。

### 步骤 4：复用 `Result`

**文件路径**：`test3/src/main/java/com/daomanliu/test3/common/Result.java`

和实验二 **完全一样**，新建 `common` 包后把 `Result` 抄过来，只改第一行包名：

```java
package com.daomanliu.test3.common;

import lombok.AllArgsConstructor;
import lombok.Data;

@Data
@AllArgsConstructor
public class Result<T> {
    private int code;
    private String msg;
    private T data;

    public static <T> Result<T> success(T data) {
        return new Result<T>(200, "success", data);
    }
    public static <T> Result<T> success(String msg, T data) {
        return new Result<T>(200, msg, data);
    }
    public static <T> Result<T> fail(int code, String msg) {
        return new Result<T>(code, msg, null);
    }
}
```

### 步骤 5：写文件控制器

**文件路径**：`test3/src/main/java/com/daomanliu/test3/controller/FileController.java`

新建包 `controller`，再建类 `FileController`，完整代码：

```java
package com.daomanliu.test3.controller;

import com.daomanliu.test3.common.Result;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.core.io.Resource;
import org.springframework.core.io.UrlResource;
import org.springframework.http.HttpHeaders;
import org.springframework.http.MediaType;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.multipart.MultipartFile;

import java.io.IOException;
import java.net.MalformedURLException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.nio.file.StandardCopyOption;
import java.util.List;
import java.util.stream.Stream;

@RestController
@RequestMapping("/file")
public class FileController {

    @Value("${file.upload-dir}")
    private String uploadDir;

    @PostMapping("/upload")
    public Result<String> upload(@RequestParam("file") MultipartFile file) {
        if (file.isEmpty()) {
            return Result.fail(400, "文件不能为空");
        }
        String fileName = file.getOriginalFilename();
        try {
            Path target = Paths.get(uploadDir).resolve(fileName);
            Files.copy(file.getInputStream(), target, StandardCopyOption.REPLACE_EXISTING);
            return Result.success(fileName);
        } catch (IOException e) {
            return Result.fail(500, e.getMessage());
        }
    }

    @GetMapping("/list")
    public Result<List<String>> list() {
        try (Stream<Path> stream = Files.list(Paths.get(uploadDir))) {
            List<String> files = stream
                    .filter(Files::isRegularFile)
                    .map(p -> p.getFileName().toString())
                    .sorted()
                    .toList();
            return Result.success(files);
        } catch (IOException e) {
            return Result.fail(500, e.getMessage());
        }
    }

    @GetMapping("/download/{filename}")
    public ResponseEntity<Resource> download(@PathVariable String filename) {
        try {
            Path file = Paths.get(uploadDir).resolve(filename).normalize();

            if (!Files.exists(file)) {
                return ResponseEntity.notFound().build();
            }

            Resource resource = new UrlResource(file.toUri());

            return ResponseEntity.ok()
                    .header(HttpHeaders.CONTENT_DISPOSITION,
                            "attachment; filename=\"" + resource.getFilename() + "\"")
                    .contentType(MediaType.APPLICATION_OCTET_STREAM)
                    .body(resource);
        } catch (MalformedURLException e) {
            return ResponseEntity.badRequest().build();
        }
    }
}
```

**逐段解释：**

#### ① 类级别前缀 `@RequestMapping("/file")`

类上写 `/file`，方法上写 `/upload`，最终路径就是 `/file/upload`。**三个接口都省了重复前缀**。

#### ② 注入配置 `@Value("${file.upload-dir}")`

把 yaml 里的 `file.upload-dir` 的值（也就是 `D:\upload`）赋给字段 `uploadDir`。

> `${...}` 是 Spring 的 **占位符**语法（不是 EL 表达式），从配置文件里取值。

#### ③ 上传接口

| 代码 | 说明 |
|------|------|
| `@RequestParam("file") MultipartFile file` | 接收表单里 **名字叫 file** 的那一部分。前端 `formData.append('file', ...)` 的 'file' 就是它 |
| `file.isEmpty()` | 用户没选文件，或选了个 0 字节文件 |
| `file.getOriginalFilename()` | 原始文件名（**可能为 null**，严谨的写法要判空） |
| `Paths.get(uploadDir).resolve(fileName)` | 拼出目标路径，如 `D:\upload\a.txt` |
| `Files.copy(inputStream, target, REPLACE_EXISTING)` | 字节流落盘，同名文件直接覆盖 |
| `catch (IOException e)` | 磁盘满、目录不存在、没权限都会走这里，返回 500 + 原因 |

#### ④ 列表接口

| 代码 | 说明 |
|------|------|
| `Files.list(...)` | 列目录（**必须关闭**，所以用 try-with-resources） |
| `filter(Files::isRegularFile)` | 只要文件，过滤掉子目录 |
| `map(p -> p.getFileName().toString())` | 只取文件名，不要完整路径（**安全**，不泄露服务器路径） |
| `sorted()` | 按字母序，展示稳定 |
| `.toList()` | 收成 `List<String>` |

#### ⑤ 下载接口

| 代码 | 说明 |
|------|------|
| `@PathVariable String filename` | 从路径 `/file/download/{filename}` 里取值 |
| `.normalize()` | 规范化，挡掉相当一部分 `../` 路径穿越 |
| `Files.exists` 判断 | 不存在返回 **404**（`ResponseEntity.notFound()`） |
| `new UrlResource(file.toUri())` | 把文件包装成可输出的资源 |
| `ResponseEntity.ok().header(...).body(resource)` | 返回 200 + 自定义头 + 文件内容 |
| `MediaType.APPLICATION_OCTET_STREAM` | 通用二进制流类型，浏览器会当下载处理 |
| 返回值是 `ResponseEntity<Resource>` | 不走 `Result`，因为响应体是**文件字节**而不是 JSON |

> 注意这个方法的返回类型**不是** `Result`。整个实验里只有它是例外，因为它要输出二进制。

### 步骤 6：放前端页面

**文件路径**：`test3/src/main/resources/static/file.html`

不用写，直接复制。它做的事：

| 行为 | 对应代码 |
|------|----------|
| 选择文件后上传 | `new FormData()` + `formData.append('file', files[0])` + `fetch('/file/upload')` |
| 页面打开就加载列表 | 脚本末尾直接调用 `loadList()` |
| 列表里每个文件给下载链接 | `<a href="/file/download/文件名" download>` |
| 下载时对文件名编码 | `encodeURIComponent(name)`，防止中文/空格导致 404 |

## 五、接口测试（Apifox）

对应 `接口测试文档.md` 中的 **「POST test3文件上传」「GET test3文件列表」「GET test3文件下载」**。

### 5.1 上传接口

| 项 | 填写 |
|----|------|
| 方法 | `POST` |
| URL | `{{baseUrl}}/file/upload` |
| Body 类型 | **form-data**（不是 json！） |
| 参数 | 类型选 `file`，值点"选择文件"，选一个本地文件（比如 `pom.xml`） |

**期望返回**：

```json
{
  "code": 200,
  "msg": "success",
  "data": "pom.xml"
}
```

断言：`$.code` = `200`，`$.data` 存在。

> 如果返回 `{"code":500,"msg":"D:\upload (系统找不到指定的路径。)"}`，说明**目录没建**，回去看步骤 2。

### 5.2 列表接口

| 项 | 填写 |
|----|------|
| 方法 | `GET` |
| URL | `{{baseUrl}}/file/list` |

**期望返回**：

```json
{
  "code": 200,
  "msg": "success",
  "data": ["pom.xml"]
}
```

断言：`$.data` 是数组，且包含刚才上传的文件名。

### 5.3 下载接口

| 项 | 填写 |
|----|------|
| 方法 | `GET` |
| URL | `{{baseUrl}}/file/download/pom.xml` |

返回的是**文件内容**而不是 JSON。Apifox 里：

- 顶部会出现 **"保存响应到文件"** 按钮，点击保存，打开确认内容一致；
- 响应头能看到 `Content-Disposition: attachment; filename="pom.xml"`；
- 响应头 `Content-Type: application/octet-stream`。

### 5.4 异常用例（做实验报告很有用）

| 用例 | 操作 | 期望 |
|------|------|------|
| 下载不存在的文件 | `GET /file/download/not-exist.txt` | HTTP **404**，无响应体 |
| 上传空文件 | 选一个 0 字节文件 | `code=400, msg="文件不能为空"` |
| 上传超大文件（>10MB） | 选一个 20MB 的视频 | HTTP **413**（`MaxUploadSizeExceededException`） |

## 七、常见问题（FAQ）

### Q1：上传报 500，提示 `系统找不到指定的路径`

`D:\upload` 没建。先在磁盘上建好这个目录，或者把配置改成 `D:/upload` 再建。

### Q2：上传报 500，提示 `getOriginalFilename() is null` 或空指针

极少数浏览器/客户端不带文件名。严谨写法应先判断：

```java
String fileName = file.getOriginalFilename();
if (fileName == null || fileName.isBlank()) {
    return Result.fail(400, "文件名无效");
}
```

> 上面的代码是"建议写法"，本实验的源码里没有加，属于正常运行不会触发的边界情况。

### Q3：Apifox 里上传返回 415

Body 类型选成了 `json` 或 `x-www-form-urlencoded`。必须选 **form-data**，并且参数类型选 **file**。

### Q4：下载中文名文件，保存下来文件名乱码

浏览器对 `Content-Disposition` 里的中文处理不一致。规范做法是用 URL 编码：

```java
String encoded = java.net.URLEncoder.encode(resource.getFilename(), java.nio.charset.StandardCharsets.UTF_8)
        .replace("+", "%20");
// "attachment; filename=\"" + encoded + "\"; filename*=UTF-8''" + encoded
```

> 同样是"建议写法"，源码保持了最简形式，英文文件名不会有问题。

### Q5：列表里能看到文件，但点下载 404

- 文件名里有没有空格/中文？前端已用 `encodeURIComponent` 处理，手工测试时要自己编码；
- 文件是不是被别的程序占用或删掉了。

### Q6：上传同名文件会报错吗？

不会。`StandardCopyOption.REPLACE_EXISTING` 会直接覆盖。

### Q7：能不能上传到项目目录里？

可以，把 `file.upload-dir` 改成相对路径或工程内路径即可，但**不建议**——重启/重新编译可能被清掉。

### Q8：为什么下载接口不用 `Result` 包装？

因为响应体必须是文件字节流。如果非要用 JSON 包，就得先 base64 编码，文件会被撑大约 33%，还要前端再解码，得不偿失。
